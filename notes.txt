PRAVAHA DEPLOYMENT NOTES
=========================

Architecture
------------
- GitHub stores the source code and triggers deployments from the main branch.
- Supabase provides PostgreSQL database storage and user authentication.
- Render runs the FastAPI backend.
- Vercel hosts the React/Vite frontend.
- The backend calls Gemini for the AI advisor.

Project repository
------------------
GitHub: https://github.com/Anudip2003/pravaha-ai
Branch: main

Supabase setup
--------------
1. Open the Supabase project SQL Editor.
2. Run backend/supabase_schema.sql.
3. Run backend/supabase_finance_settings.sql.
4. Configure Authentication > Providers > Email.
5. Copy the Supabase URL and API keys from Project Settings > API.

Render backend setup
--------------------
Service type: Web Service
Root Directory: backend
Language: Python
Branch: main
Build Command: pip install -r requirements.txt
Start Command: uvicorn app.main:app --host 0.0.0.0 --port $PORT
Python version environment variable:
  PYTHON_VERSION=3.11.11

Render environment variables
----------------------------
SUPABASE_URL=the Supabase project URL
SUPABASE_ANON_KEY=the Supabase anon/public key
SUPABASE_SERVICE_ROLE_KEY=the Supabase service-role key
GEMINI_API_KEY=the Google AI Studio API key
FRONTEND_ORIGIN=https://pravaha-ai.vercel.app
PYTHON_VERSION=3.11.11

The service-role key and Gemini key are private. Add them only to Render.
Never commit them to GitHub or add them to Vercel.

Backend health check
--------------------
Open this URL after Render deploys:
  https://pravaha-ai.onrender.com/health
Expected response:
  {"status":"ok"}
A 404 response at / is normal because the API has no root page.

Vercel frontend setup
---------------------
Root Directory: frontend
Build Command: npm run build
Output Directory: dist

Add this Vercel environment variable:
  VITE_API_URL=https://pravaha-ai.onrender.com

VITE_API_URL is safe to expose because it is only the public backend URL.
If Vercel warns about the VITE_ prefix, create it as Config. If an existing
Secret cannot be changed, delete it and create it again as Config.

Deployment order
----------------
1. Push code to GitHub.
2. Deploy the Render backend.
3. Test the /health endpoint.
4. Deploy the Vercel frontend.
5. Set VITE_API_URL in Vercel and redeploy the frontend.
6. Set FRONTEND_ORIGIN in Render to the real Vercel URL.
7. Save and redeploy the Render backend.
8. Open https://pravaha-ai.vercel.app and test signup, login, expenses,
   historical month selection, monthly comparison, budget alerts, cash flow,
   CSV import, and the AI chatbot.

Updating the application
------------------------
From the project root:
  git add -A
  git commit -m "Describe the change"
  git push origin main

Render and Vercel can deploy the new main-branch commit automatically.
Supabase data remains stored when the application is redeployed.

Local development
-----------------
Backend:
  cd backend
  venv\Scripts\activate
  pip install -r requirements.txt
  uvicorn app.main:app --reload

Frontend, in a second terminal:
  cd frontend
  npm install
  npm run dev

Local frontend: http://localhost:5173
Local backend: http://localhost:8000

Security checklist
------------------
- Never commit backend/.env.
- Never commit backend.zip, venv, node_modules, or dist.
- Keep SUPABASE_SERVICE_ROLE_KEY and GEMINI_API_KEY only in Render.
- The keys previously displayed in chat were exposed; revoke and regenerate
  them before public production use.
- After rotating keys, update the new values in local .env and Render.
